## Summary

ironwork 0.9.0 is the release candidate. Programs run on the VM by default, every ending IBM's books document carries Language Environment's message, every diagnostic and run-time refusal has a catalogued id, the load module format is frozen at 1.0, and a conformance report ships with each release. `--compliance extended` reads about fifty more GnuCOBOL and Micro Focus forms.

- **VM by default:** `run` and `cics` run a program on the VM, and `--interpret` keeps the interpreter. On hosted runners the VM takes 0.14 to 0.17 of the interpreter's time on callheavy, packed and tblsrch, and 0.6 to 0.8 of cobc's on seqio: every target of decision D-4 is met.
- **Endings as IBM documents them:** an I/O failure nothing handles, an intrinsic function's argument outside its domain, a CALL of a missing program, control past a main program's last line, zero raised to a negative power, a program check, and the rule breaks of SORT, MERGE, XML PARSE, CANCEL and EXTERNAL each end U4038 with Language Environment's message id and text. A job step's return code is RETURN-CODE modulo 4096.
- **CALL by IBM's scope rules:** a contained program is reached only from the program directly containing it, or from any program its container holds when it is COMMON. CANCEL acts only on a program a dynamic CALL entered.
- **Formats at version 1:** the load module at 1.0, with 1.1 adding each program's facts and 1.2 the split keys; the run journal, SQL recording, fuzz manifest and statement list each at version 1. A 0.x load module is refused.
- **Ids on every message:** a run-time refusal (IWR0058 to IWR0077), a JCL or utility message (IWJ0001 to IWJ0251) and the Communication feature (IWS0102) carry catalogue ids, as compile messages did from 0.8.0.
- **Evidence names its assumptions:** each register entry says which statement kinds, usages and options it governs, and a run journal's close record lists the ids the run's programs met, which cobolwork copies onto its label rows.
- **Conformance with each release:** `tools/conformance.py` writes the report CI attaches: CCVS85 by module, the corpus census, the assumptions by basis, Hercules, the interpreter-against-VM campaign and Db2. The 0.9.0 campaign ran 2,591,274 inputs over 187 CCVS85 programs, 165 batch and 22 subprograms, in 24 CPU-hours, and the two executors agreed on every one. `ironwork-oracle witness` writes the record a licensed site publishes after running the deck, and STABILITY.md says what holds from 1.0.
- **Enterprise COBOL's own reading under strict:** four forms IBM flags, a statement in Area A, a missing period before PROCEDURE DIVISION and a stray scope terminator each at E with the compile going on at return code 8; the Communication feature refused as IBM refuses it; three refusals IBM's published listings show and ironwork lacked; four constructs those listings show IBM compiling that ironwork refused; conditional compilation; and ALLOCATE and FREE, which now run.
- **Extended reads more:** BINARY-CHAR and GnuCOBOL's sized binary usages, COMP-X, FLOAT-SHORT and FLOAT-LONG, ANY LENGTH, BASED, PROGRAM-POINTER, a table at level 01 or 77, screens, environment variables, record locking, PERFORM FOREVER, INSPECT TRAILING, CALL RETURNING OMITTED, the OMITTED condition, STOP RUN RETURNING, Micro Focus's split keys and file forms, and more. Each carries an IWX warning, and docs/compliance.md lists them all.

**Limit:** no IBM compiler has witnessed any of this. The conformance report says what each kind of evidence shows, and the 244 Chosen assumptions wait on IBM's own output. A construct the VM does not run yet stops with a line saying to run the program with `--interpret`.

## Added

- `run` and `cics` run on the VM by default, and `--interpret` runs on the interpreter. A program code generation refuses runs on the interpreter with a line naming what was refused, and `--vm` still refuses it with 242. A run journal's close record names the executor. Over the 1,027 programs of a 3,000-program corpus sample that compiled when the switch was made, the two gave the same exit status and output for each.
- `--time-limit SECONDS` and `--storage-limit BYTES` on `run` and `job`, each checked as a statement starts and ending the run S322 or at the next statement; a run stays unlimited without them. SECURITY.md lists every limit and the processes ironwork starts.
- An I/O failure that no FILE STATUS holds and no declarative takes ends U4038: IGZ0035S for a failed OPEN or CLOSE, IGZ0020S for a logic error, IGZ0197S and IGZ0002S for a permanent error, and ironwork's own text where IBM names no message. An OPEN or CLOSE of a VSAM file returns control whatever its status (C451).
- An intrinsic function's argument outside what it takes ends U4038 with IBM's message, IGZ0156S for FACTORIAL, IGZ0163S for RANDOM, IGZ0159S to IGZ0161S for the integer dates and the rest; SQRT, LOG, LOG10, ASIN, ACOS and the trigonometric functions end with the math services' CEE2010E to CEE2017E, and an invalid HEX-TO-CHAR or BIT-TO-CHAR character with IGZ0152S (C452).
- A dynamic CALL of a missing program ends U4038 with CEE3501S, and a static one stops with the binder's IEW2456E; a job step whose program no library holds still ends S806 (C450).
- A main program whose control runs past its last statement ends U4038 with IGZ0037S at its last paragraph; a called program still returns (C456).
- Zero raised to a negative power ends U4038 with IGZ0050S, which ON SIZE ERROR takes, and a power that truncates to zero under a negative exponent ends with IGZ0222S. A fixed-point exponent outside 0 to 31 runs as the Programming Guide multiplies it (C334).
- A program check carries CEE3206S to CEE3215S's texts; NUMCHECK's IGZ0278S, IGZ0279W, IGZ0315S and IGZ0316W and PARMCHECK's IGZ0317S and IGZ0318W; an INVOKE that finds no method IGZ0045S; a recursive CALL of an outermost program IGZ0015S (C455). STOP RUN, GOBACK or EXIT PROGRAM in a SORT or MERGE procedure ends IGZ0012S, a SORT inside another IGZ0173S, GOBACK in an XML PARSE procedure IGZ0227S, and a CANCEL of an active program or an EXTERNAL item of another size IGZ0032S, IGZ0066S or IGZ0075S (C453). A CICS task reports such a condition as transaction abend 4038 (C454). A reference beyond the run unit's storage ends S0C4 (C458).
- A CALL reaches a contained program by Enterprise COBOL's scope rules (C470), and a duplicate PROGRAM-ID within a compilation is refused with IWC0295. `--program-scope flexible` restores the search by name, `--unresolved-calls fail` refuses a static CALL naming no program of the compilation, its bundle or the Language Environment's services (IWC0296), and `--le-services bind` has a CALL of a service's name reach the service first.
- The load module format is 1.0, which this ironwork writes and every 1.x reader reads. 1.1 adds an optional FACTS section holding each program's statement kinds and usages, and 1.2 carries split keys after the LIR section's table ranges. `ironwork dump` shows both. The fuzz manifest and journal schemas leave each object open, and a statement list is version 1 with no header.
- Every refusal a run reaches carries an id, IWR0058 to IWR0077, in both executors; the JCL reader, COND and IF expressions, IDCAMS, DFSORT, SYMNAMES and refused steps carry IWJ0001 to IWJ0251; a user-defined function reached at run time is IWR0075. docs/messages.md lists both halves.
- The Communication feature is read through and each item refused where it stands with IWS0102, under every option, as Enterprise COBOL's Migration Guide has it.
- Each assumption in the register names the statement kinds, data usages and options it governs, `ironwork assumptions --json` publishes them, and a run journal's close record lists every id some program of the run met on its own (one program must meet all of a conjunction).
- `tools/conformance.py` writes the conformance report CI attaches to each release; `tools/census.py --json` tallies a corpus sample by return code and first refusal; a Hercules reading names Hercules's version and ironwork's; `docs/conformance/differential.json` keeps a campaign's totals; `tools/differential-campaign.py` and the Differential campaign workflow run fuzz --differential over a corpus for a CPU budget, each program in the mode that fits it, batch, CICS or interface.
- `fuzz --cics --differential` and `fuzz --interface --differential` compare the two executors on CICS tasks and subprograms; `cics --task-out` writes each task's RETURN TRANSID, COMMAREA and queues, and `run --arguments-out` each argument as the caller sees it. A differential run that ends at the statement limit is compared, and only one that ends at the timeout goes uncompared.
- Fuzz guides its runs by coverage: a run that reaches a new statement or paragraph is kept and half the later runs change a kept one, a field the program compares with a literal now and then holds it, and each run stops at `--hang-limit` statements with S322. A field a CALL takes its program name from holds a name a caller would pass. Each CALL that passes fewer bytes than the callee describes is named before the runs.
- `job --trace-input` follows a job's in-stream data through each step's programs.
- `ironwork-oracle witness` writes a publishable record of a witness deck run: the deck, the compiler and its options, a hash of each spool file and the counts of cases and assumptions that held, with no byte the compiler produced. docs/witness.md is the runbook and the ledger of records received.
- STABILITY.md states what holds from 1.0, what a minor may change and what carries no promise; SECURITY.md gives the supported versions and how to check and rebuild a download; the README says what 1.0 claims about conformance and lists every extended form; docs/evidence.md maps each kind of evidence to NIST SP 800-53 and COBIT 2019.
- CI tests on macOS, Windows and Linux arm64 and checks a build on Rust 1.95, the declared minimum; a release attests a CycloneDX bill of materials for each build, builds the Linux binary twice from two paths and compares the bytes, reports API changes against crates.io, and refuses a tag whose commit lacks its notes; Scorecard runs weekly; the Bench workflow times `tools/bench.sh` on hosted Linux x86-64 and macOS runners.
- Under strict: a numeric VALUE for a numeric-edited item, END-DISPLAY and END-ACCEPT, and VALUES outside a level-88 entry are refused as IBM refuses them (IWC0292, IWS0097, IWS0098); a user-defined word past 30 characters is cut at E (IWS0099); a statement in Area A is read as though in Area B at E (IWS0100); a stray scope terminator is discarded at E (IWS0104); a missing period before PROCEDURE DIVISION is assumed at E (IWS0105); an arithmetic receiver that is neither numeric nor numeric-edited (IWC0323), a LABEL RECORDS data-name that is not defined (IWC0324) and RECORDING MODE F over records of differing size (IWC0325) are refused as IBM's listings show them refused.
- An index of a GLOBAL table is the declaring program's item in a contained program, VOLATILE is read, WHEN-COMPILED holds the compile time, a parenthesised condition is an EVALUATE subject, and >>DEFINE, >>IF, >>ELSE and >>END-IF choose lines under strict as Enterprise COBOL 6.3 has them.
- ALLOCATE and FREE run on both executors, with INITIALIZED, RETURNING and CHARACTERS, from the heap CEEGTST takes from (C487). LENGTH OF a record no OCCURS DEPENDING ON varies is the compile's length before the record has an address.
- A user-defined function may take an intrinsic function's name but LENGTH, RANDOM, SIGN, SUM and WHEN-COMPILED, and PGMNAME forms its external name from the source's CBL and PROCESS cards; a callable service sets RETURN-CODE to 0 (L12).
- Under `--compliance extended`, each with its IWX warning and checked against cobc 3.2's output on both executors: BINARY-CHAR (C460) and SIGNED-SHORT, UNSIGNED-INT, BINARY-LONG-LONG and the other sized usages; COMP-X and PIC X(n) COMP-5 (C467, C468); FLOAT-SHORT and FLOAT-LONG as COMP-1 and COMP-2 (C469); a table at level 01 or 77 (C461); a level-66 entry inside its record (C471); ANY LENGTH parameters (C481); BASED items and PROGRAM-POINTER (C486); Micro Focus's split keys (C484), START KEY <, an FD with no FILE SECTION header and ASSIGN TO DISK (C482, C483); LOCK MODE, SHARING, WITH LOCK and UNLOCK, read and dropped (C465).
- Also under extended: DISPLAY and ACCEPT on one 24-by-80 screen with AT, LINE, COLUMN and the field phrases, the SCREEN SECTION, ACCEPT FROM LINES and COLUMNS and COB-CRT-STATUS (C462, C463, C489); ACCEPT FROM ENVIRONMENT, SET ENVIRONMENT and `run --env` (C464); PERFORM FOREVER and PERFORM UNTIL EXIT; INSPECT TALLYING and REPLACING FOR TRAILING (C466); CALL RETURNING OMITTED; the OMITTED condition; STOP RUN and GOBACK RETURNING (C480); PROCEDURE DIVISION CHAINING (C488); BEFORE ADVANCING on a line-sequential file; DELETE FILE (C485); DISPLAY UPON SYSERR; INITIALISE; an inline PERFORM VARYING with AFTER; FREE of a LINKAGE or BASED record; FUNCTION MODULE-CALLER-ID, STORED-CHAR-LENGTH and CONCATENATE; an unsigned integer as a character function's argument; doubled periods and COPY name..; >>ELIF, >>D, >>TURN, >>LISTING and >>PAGE; and a file read again in free form when a literal runs past column 72.
- cobolwork's CICS tables with 61 more commands, WEB, DOCUMENT, INQUIRE, SET and the asynchronous API among them, each refused by name when a task reaches it.
- A SQL recording writes DATE, TIME and TIMESTAMP columns typed, and a `# text:` line after each call with the statement in full, which replay matches whole.
- JCL replaces a symbol a PROC, EXEC or SET statement defines inside a PARM's apostrophes, and a doubled ampersand is one.

## Changed

- A statement that begins in Area A compiles at return code 8 under strict, as IGYPS0009-E has it; in the corpus census about a tenth of cleanly compiling programs move to return code 8 and still run.
- A job step's return code is RETURN-CODE modulo 4096, as STOP RUN returns it, where ironwork clamped it to 0 to 4095 (C457). CEE3ABD without clean-up leaves the run unit's files as an abend under TRAP(OFF) does.
- CANCEL resets only a program a dynamic CALL entered, and the programs it contains with it.
- A program check, NUMCHECK, PARMCHECK, INVOKE and recursion endings carry IBM's ids and texts in place of ironwork's; the endings ON SIZE ERROR and FASTSRT decide on now travel in the abend code rather than in the message's first word. docs/dialect.md lists the endings cobc gives otherwise.
- DISPLAY of a COMP-1 or COMP-2 item shows the value as the Language Reference gives it, where it ended the run with IWR0066.
- FUNCTION LENGTH of a numeric, floating-point or pointer item counts its bytes, as IBM and cobc do, where it gave the digits.
- The statement limit counts CONTINUE and EXIT: a loop of nothing else ends S322, as z/OS ends a step past its TIME= (C241).
- SET in a dynamic statement string reaches the database only for a special register, PATH or SCHEMA; a SET assignment and SET SESSION TIME ZONE are refused by name (C402). DESCRIBE gives an unsized decimal as DECIMAL(31,6), writes SQLNAME in the code page cut to whole characters, and checks SQLN only against what it writes (C403).
- The workspace crates pin each other at their exact version, and the Rust API carries no promise (operator ruling 2026-10-07); the semver job reports changes without holding a release. Code generation lives in the compile crate as `ironwork_compile::lower`, and exec re-exports it.
- `ironwork check` finds a reference's candidates by name rather than by scanning every item: a 151,659-line program checks in 0.38 s of user CPU, from 5.0 s.
- The VM locates constant-address places and reads integer operands directly, carries scaled decimals and a fixed-point step's value as counts, stores a counted result into a packed receiver directly, takes FUNCTION MOD of two counts without the intrinsic, builds a CALL's activation where it runs, reaches a static CALL's program once per activation and keeps argument lengths without allocating per call.
- Native code generation follows in 1.1 whatever the VM measures (operator, 2026-10-07); docs/benchmarks.md records the hosted runs.
- A release's notes are committed as docs/releases/<version>.md before the tag, and docs/releases holds the notes of 0.1.1 to 0.8.0 as published. RELEASING.md refreshes docs/conformance before the version commit and says how to withdraw a bad release from each registry.
- Fuzz tells refusals by where they stopped, each with its count, and counts timeouts apart from runs that agreed at the limit.

## Removed

- The readers for load module formats 0.5 to 0.7. A 0.x module is refused, naming 1.x; compile the source again.
- The per-subscript SSRANGE check from the LIR, which code generation has not written since the check moved to the composed address.
- IWR0015, the refusal of an index declared in a GLOBAL table of a program containing others; the index is read now.
- IWC0107 as the id of the user-defined function gap, which is IWR0075; IWC0107 is not given to another message.

## Fixed

- EVALUATE (A = B) ALSO C was refused with "expected ')'": a subject that is no arithmetic expression is read as a condition.
- Zero raised to -1000000000 ended with IGZ0050S; the exponent is cut to nine digits before its sign is read.
- IGZ0037S was placed at line 0 of the source; it is placed at the last paragraph.
- A CALL out of scope, a missing program and a Language Environment service ironwork does not provide all ended S806 by ironwork's choice; each ends as IBM documents.
- The register's claims on a callable service's RETURN-CODE, a user-defined function named as an intrinsic one, PGMNAME and CEE3ABD's dump departed from the Enterprise COBOL 6.4 manuals.
- CICS's INVMPSZ with no handler abended AEIP, the fallback, where CICS's table gives AEYB. A HANDLE ABEND exit does not take the 4038 a Language Environment condition ends a task with (C454).
- SQLNAME could hold stale bytes for a name the code page could not encode; DESCRIBE abended on an unsized decimal; a PostgreSQL message longer than 64 MiB is refused rather than allocated.
- A stale evidence lock's holder was taken as gone on Windows; tasklist now answers there.
- Fuzz's 2-second timeouts hid six S806 programs under load, every interface run CALLed a generated program name, `--timeout` given as a float reached fuzz as a usage error, and the campaign skipped every program with EXEC CICS.
- A release dry run on main failed at the semver job; the job gates only a tag push. The Linux bench job fell over when GNU's mirror did not answer; it retries and falls back to ftp.gnu.org.
- The LOWER-CASE, REVERSE, TRIM and UPPER-CASE of a numeric item compiled silently and ended the run IRONWORK; strict refuses it with IWC0297-S.
- ASSIGN TO DA-MASTER looked up a DD named DA-MASTER alone, and an IBM job's //MASTER DD left the OPEN at status 35; the name as written is tried first, then the DD name after the last hyphen, as Enterprise COBOL reads the label.

## Upgrading

- Compile every program again: a 0.x load module is refused.
- `run` and `cics` use the VM. Pass `--interpret` for the interpreter. A program code generation refuses falls back to the interpreter with a line saying so, and `--vm` refuses it with 242 as before.
- A CALL of a contained program from outside IBM's scope is now a missing program: `--program-scope flexible` restores the search by name.
- A main program that ran off its last line ended normally and now abends U4038 with IGZ0037S: end it with GOBACK or STOP RUN.
- A CALL of a missing program, an I/O failure nothing handles, an intrinsic argument outside its domain and a construct ironwork cannot run no longer end S806, IO-nn or IRONWORK: a JCL IF test on ABENDCC, a fuzz expectation or a test that read those codes reads U4038 and the message's id now. docs/messages.md and docs/dialect.md list them.
- A RETURN-CODE above 4095 wraps where it was clamped.
- A loop of only CONTINUE or EXIT now ends S322 at the statement limit.
- Run journals carry the executor and the assumption ids in the close record. cobolwork 0.9.0's kinds table takes both; an older verifier refuses them.
- A SQL recording opens with its version 1 header and writes dates typed; a recording that gives them as `char:` replays unchanged, and one headed with another version is refused.
- A load module with split keys is format 1.2, which a 1.1 reader refuses as malformed.
- The crates pin each other at `=0.9.0` and promise no Rust API; code generation is `ironwork_compile::lower`.
